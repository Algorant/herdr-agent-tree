## Description

The first live `just deploy` with the new reload action reported success, but an immediate post-command verification observed the lock holder executing `/home/ivan/.local/share/herdr-agent-tree/.stage-old.<pid>/src/agent-tree (deleted)` rather than the new staged binary. The verification wrapper failed and restored the config; shortly afterward a new lock holder from the current staged binary appeared, likely after `herdr server reload-config`. This suggests the action invocation can use Herdr's cached pre-relink plugin command until config reload refreshes registration. Reproduce the sequence against a real isolated Herdr server, establish the exact ordering, and fix deploy so it returns only when the stable sole subscriber executes the just-staged hash with no later handoff.
