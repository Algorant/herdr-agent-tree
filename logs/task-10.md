Algorant's simplified direction after an Opus 5.5 adversarial review (2026-09-29): this is a SMALL Agent Tree feature, not a recency subsystem. Previous Worker attempts were discarded; no task-10 source was merged. Do not salvage their large checkout, add a new E2E harness, or preserve their per-pane subscriptions, server-pid pinning, separate recency database, restart-recovery state machine, fault-injection framework or tearing monitor.

Product behavior: every recognized top-level agent (Pi or non-Pi) is a singleton/family root. A real agent state_change_seq rise in any member promotes its WHOLE outermost family above older families globally across machines. Preserve existing nested delegation (Worker-owned Subagent stays under Worker), parent-first preorder and branch markers; children do not independently reorder. Output-only, focus, display, and own metadata writes do not count. Practical wall-clock stamps may misorder near-simultaneous transitions on unsynchronized machines; document this instead of blocking the feature.

One direct implementation path to validate: use the EXISTING subscriber's 500ms timeout as the wake-up, checking the current snapshot/agent state sequence every ~1–2 seconds. No per-pane status subscriptions or connection swaps. Track minimal (terminal_id, last seq) in subscriber memory. First snapshot is a neutral baseline; a genuine new agent after baseline may count as activity. On seq rise, stamp local wall-clock time and publish a fixed-width recency-leading rank shared by every member of the same validated family, followed by existing endpoint-qualified preorder. Obtain a family stamp from already published rank tokens rather than a second persistent store. One-shot apply/reload/toggle must read existing rank values without stamping. On clean stop/server restart, a neutral baseline and reordering on NEXT actual activity is acceptable; exact pre-restart order and downtime transitions need not be preserved. Use an explicit bounded response to malformed required data; do not invent silent fallback paths.

Validation scope: a few focused unit tests for sequence change, family fold/parent-first, newest-first rank and prefix readback; update ONLY existing sidebar/toggle E2E rank-format assertions as needed, do NOT add tests/e2e/recency.sh or extend scripts/check.sh with another E2E. Run the project's existing scripts/check.sh and cargo build --locked --release. After review, obtain Algorant's explicit approval for a short live merged-client check before acceptance. No live edits, push or release without approval.
